# RBAC — Decisions & assumptions

Tag `[REVIEW]` = the human should confirm. Each decision appears once, in its final form.

- D1 **Role mapping (confirmed).** Existing `master` → Super Admin (unique org owner). Existing `admin` → Sub Admin with an **empty grant set**: it keeps reading usage but has no budget pool, models or sharing until the Super Admin grants them. Existing `user` → Member. Reason: fail closed, no escalation.
- D2 **Role storage (confirmed).** Roles stay on `UserRecord.role` (`user|admin|master`). Super Admin = `master`; Sub Admin = `admin`; Group Admin = a `team_memberships` row with role `group_admin` (per team, never global); Member = everyone else. Keeps the single-admin flow working with no data rewrite. The platform keeps exactly one master.
- D3 **Money and unpriced models (confirmed).** Money is integer micro-USD (1 USD = 1,000,000), computed from the price table at debit time; no floats in budgets or the ledger. **Fail closed:** under a hard-limit budget, a call to a model with no price is blocked with `MODEL_NOT_PERMITTED` (reason `"unpriced"`), unless an admin sets an explicit per-model override (a stored `unpriced_override` for that model: allowed, debited at a configured per-token rate or 0). Soft-limit and unbudgeted calls to unpriced models are allowed, counted in tokens and logged as unpriced.
- D4 **Agents have no table**, so a share is a grant on `(project_id, agent_id)`; a whole-project share uses `agent_id = "*"`.
- D5 **No migration tool exists** (document store). "Migrations" are idempotent, lazy backfills on first use (like the existing knowledge migration), plus a reversible `scripts/` helper (P1.3 / P7.3). A project or user the backfill has not reached reads as the safest value: owner-only, plain member, no team. After the backfill, existing projects are in the Default team per D6, still owner-only.
- D6 **Existing projects go into one "Default" team, but stay owner-only (user chose the Default team; this variant is my pick of option (b) because the choice was left blank — [REVIEW]).** The backfill creates the Default team lazily, adds every existing user as a member and the master as its group admin, and sets each existing project's `team_id` to Default with `team_access = false` (owner-only). Team membership therefore does NOT expose a pre-existing project; only the owner, the master/Sub Admin scope and explicit grants do. A project becomes team-visible only when its owner or an admin sets `team_access = true`. Test: a Default-team member cannot see another user's pre-existing project. Reversible: the helper restores `team_id = None`.
- D7 **Typecheck/lint:** none configured for the backend; the gate is the full pytest suite (+ frontend lint/tests when the frontend is touched). No new tool added.
- D8 [REVIEW] **Project visibility.** Owner and Super Admin see a project. Team members see it only when `team_access` is true. A group admin gets no extra visibility, only management rights (edit/share) over team-visible projects of their own team. A Sub Admin has **no blanket project access** (today's admins never see project contents; this keeps that privacy stance) and gets reach only through grants/shares. Super Admin seeing every project follows the spec ("Everything") and amends the earlier rule that no admin sees project contents - [REVIEW].
